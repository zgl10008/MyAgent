# 智能健康管理 Agent 平台：五分钟项目介绍

面试官您好，我介绍一下我做的 **智能健康管理 Agent 平台**。

这个项目是一个基于大语言模型的健康咨询类 Agent 系统，主要面向用户的多轮健康问答场景。它不是做医疗诊断，而是提供非诊断型的健康建议辅助，比如饮食、运动、慢病管理、体检指标解释、日常健康知识咨询等。

我做这个项目时，核心想解决普通 LLM 在健康咨询场景里的三个问题：

1. 回答容易缺少可靠知识支撑，存在幻觉风险。
2. 多轮对话中容易遗忘用户上下文，个性化能力弱。
3. 复杂问题往往需要拆解、检索、工具调用和综合推理，单轮问答不够稳定。

所以整体架构上，我把系统拆成了四层：用户交互层、Agent 编排层、知识增强层和记忆管理层。

## 1. Agent 编排层

首先是 Agent 编排层。我设计了一个任务规划与执行框架。

用户输入进来后，系统会先做意图识别和任务复杂度判断。对于简单问题，比如“高血压患者饮食要注意什么”，系统会走比较直接的 RAG 问答流程；对于复杂问题，比如“我最近血压偏高、睡眠不好、体检血脂也高，帮我分析一下日常应该怎么调整”，系统会进入 Agent 工作流。

在 Agent 工作流里，我设计了条件路由机制，根据任务类型选择不同执行策略：

- 对于需要边推理边调用工具的问题，采用类似 `ReAct` 的模式，让模型交替进行思考、行动和观察。
- 对于目标明确但步骤较多的问题，采用 `Plan-and-Execute` 模式，先生成任务计划，再逐步执行。

这样做的好处是，复杂咨询不会直接让模型一次性生成答案，而是先把问题拆成多个子任务，例如提取用户健康信息、检索相关知识、判断风险提示、生成建议、补充注意事项等，最后再统一汇总。

## 2. RAG 知识增强模块

第二块是 RAG 知识增强模块。

健康咨询场景对知识准确性要求比较高，所以我没有完全依赖模型自身参数知识，而是构建了一个混合检索系统。知识库里会接入健康科普文档、疾病管理指南、营养运动建议等资料。文档进入系统后，会经过解析、清洗、分块，然后做向量化存储。

检索时，我用了关键词检索和向量语义检索结合的方式：

- 关键词检索适合命中明确术语，比如“高血压”“低密度脂蛋白”。
- 向量检索适合处理用户的自然语言表达，比如“最近总是头晕是不是和血压有关”。

两路召回之后，我使用 `RRF` 倒数排名融合策略做重排序，把两种检索结果融合起来，提升相关知识召回的稳定性。最终回答时，模型会基于检索到的内容生成建议，尽量减少幻觉，并保证回答有知识依据。

## 3. 记忆管理机制

第三块是记忆管理机制。

健康咨询很依赖上下文，比如用户的年龄、性别、既往症状、饮食习惯、历史咨询记录等。如果每次都当成新会话，体验会很差；但如果把所有历史对话都塞进上下文，又会导致 token 成本高、噪声多。

所以我设计了多层记忆：

- 短期记忆用 `Redis` 保存当前会话窗口，保证多轮对话连续。
- 中期记忆用 LLM 对历史对话做摘要压缩，保留关键健康信息，减少上下文长度。
- 长期记忆用 `PostgreSQL` 保存结构化会话信息，并结合 `Milvus` 存储语义向量记忆，用于跨会话召回。

比如用户前面说过“我有高血压”，后面问“那我还能喝咖啡吗”，系统可以理解这个问题和前面的健康背景有关。如果用户隔几天再次咨询，也可以召回之前提到过的血压、睡眠、饮食偏好等信息，从而生成更个性化的回答。

## 4. 工具调用能力

第四块是工具调用能力。

在健康咨询场景里，有些问题不能只靠文本生成，比如 BMI 计算、热量估算、健康指标范围查询、知识库检索等。我把这些能力抽象成外部工具，由 Agent 根据任务需要自动选择调用。工具调用结果会进入执行状态中，最后由模型综合生成自然语言回答。

## 5. 工程难点

这个项目里我重点解决了几个工程问题。

第一个是 Agent 流程稳定性。因为模型输出有不确定性，所以我没有让模型完全自由发挥，而是设计了任务状态跟踪机制，包括当前步骤、工具调用结果、异常信息和最终输出状态。如果某个步骤失败，比如检索结果为空或工具调用异常，系统会走降级逻辑，而不是直接报错或生成不可靠答案。

第二个是检索准确性。单纯向量检索在专业词命中上不够稳定，单纯关键词检索又不适合口语化问题，所以采用混合检索加 `RRF` 融合。这个方案在健康问答里比较实用，因为用户表达往往不专业，但知识库内容又比较专业。

第三个是上下文管理。我通过滑动窗口、摘要压缩和长期语义记忆，把上下文拆成不同层级，既保证当前对话连贯，又避免历史信息无限膨胀。

## 6. 工作流程例子

我举两个例子说明系统是怎么工作的。

第一个例子是简单健康知识问答。用户问：“高血压患者饮食要注意什么？”系统先识别这是一个健康知识问答，任务复杂度不高，于是进入 RAG 流程。系统会从知识库中同时做关键词检索和向量检索，召回与高血压饮食、限盐、控制脂肪摄入、运动建议相关的文档片段，再通过 `RRF` 融合排序，选出最相关的内容交给模型。模型最后基于检索内容生成回答，并提醒用户这类建议不能替代医生诊断。

第二个例子是复杂多轮咨询。用户说：“我最近血压偏高，睡眠也不好，体检发现血脂偏高，帮我看看怎么调整。”系统会先判断这是一个多因素综合健康咨询，不适合直接回答，于是进入 Agent 工作流。Agent 会先拆解任务：提取用户健康问题，读取历史记忆中是否有年龄、既往病史、饮食习惯等信息，检索高血压、血脂异常和睡眠相关知识，必要时调用计算或指标解释工具，然后把各步骤结果汇总成生活方式建议。回答时会分成饮食、运动、睡眠、监测和就医提醒几个部分，同时避免给出确定性诊断。

## 7. 项目总结

如果让我总结这个项目的价值，我觉得它不只是一个简单的 LLM 聊天应用，而是围绕健康咨询场景做了比较完整的 Agent 工程化设计，包括任务规划、工具调用、知识增强、记忆管理和异常处理。

通过这些模块，系统可以更稳定地处理多轮、复杂、个性化的健康咨询问题。

后续如果继续优化，我会重点做四件事：

1. 补充更严格的健康安全边界，比如高风险症状识别和就医提醒。
2. 加入回答引用来源，提高可追溯性。
3. 融合知识图谱，把疾病、症状、指标、药物、饮食禁忌等实体和关系结构化，增强复杂健康问题中的关系推理能力。
4. 建立评测集，从检索命中率、回答准确性、上下文一致性和安全性几个维度持续评估 Agent 效果。
