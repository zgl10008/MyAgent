### 2.1 `react_agent.py` — ReAct 循环（291 行）

**这是整个项目最核心的文件**。实现经典的 Thought → Action → Observation 循环。

#### System Prompt 模板

```python

## 输出格式
### 若需要调用工具：
Thought: <为什么要用工具>
Action: <工具名>
Action Input: <JSON 参数>

### 若可直接作答：
Thought: <依据>
Final Answer: <完整答案>
"""
```

#### 核心解析函数 `_parse_react_step()`

```python
def _parse_react_step(text: str) -> Dict[str, Any]:
    # 1. 用正则提取 Thought（多行，直到 Action 或 Final Answer）
    thought_m = re.search(r"Thought:\s*(.+?)(?=\n(?:Action:|Final Answer:)|\Z)", text, re.S)

    # 2. 检测 Final Answer → 标记完成
    if re.search(r"Final Answer:\s*", text, re.I):
        fa_m = re.search(r"Final Answer:\s*(.+)\Z", text, re.S)
        out["final_answer"] = fa_m.group(1)
        out["done"] = True

    # 3. 提取 Action 和 Action Input
    action_m = re.search(r"Action:\s*(\S+)", text)
    input_m = re.search(r"Action Input:\s*(\{[\s\S]*\})", text)  # JSON
    # 4. 宽松匹配兜底：非 JSON 块后的 JSON 也尝试解析
    loose = re.search(r"Action Input:\s*([\s\S]+?)(?=\n\n|\Z)", text)
```

**面试要点**：正则解析脆弱但可控。生产环境应换 OpenAI function calling 模式，但这里手写正则体现了对 ReAct 的底层理解。

#### 主循环 `ReActAgent.run()`

```python
async def run(self, query, context):
    for step_idx in range(self.max_steps):          # 最多 10 步防死循环
        # 1. 构造消息：system prompt + 检索记忆 + 用户问题 + 历史步骤
        messages = [
            {"role": "system", "content": REACT_SYSTEM_PROMPT + memory},
            {"role": "user", "content": user_prompt},
        ]

        # 2. 调用 LLM
        raw = await self._llm.acomplete(messages, temperature=0.2)

        # 3. 正则解析输出
        parsed = _parse_react_step(raw)

        # 4. 如果是 Final Answer → 写入记忆 → 返回结果
        if parsed.get("done"):
            await self._memory.append_turn(session_id, "assistant", answer)
            return AgentResult(success=True, final_answer=answer)

        # 5. 否则执行工具，把 Observation 追加到历史
        obs = await self._tools.invoke(action, action_input)
        history_lines.append(f"Observation: {obs}")
        # 继续下一轮循环

    # 超步数 → 返回失败
    return AgentResult(success=False, error="达到最大步数")
```

**关键设计**：
| 设计点 | 实现 |
|--------|------|
| 防死循环 | `max_steps=10` |
| 温度控制 | `temperature=0.2`（低随机性，严格遵循格式） |
| 工具校验 | 检查 `action in tool_names`，防止模型编造工具 |
| 观察截断 | `obs[:8000]`，防止巨量文本撑爆 context |
| 记忆联动 | 答案生成后自动写入记忆 |
| 错误兜底 | LLM 失败、解析失败、工具异常都有对应处理 |

**协议抽象**：
```python
class LLMCallable(Protocol):
    async def acomplete(self, messages, **kwargs) -> str: ...

class MemoryLike(Protocol):
    async def get_relevant(self, session_id, query, limit) -> List[str]: ...
    async def append_turn(self, session_id, role, content, metadata) -> None: ...

class ToolInvoker(Protocol):
    async def invoke(self, name, arguments) -> str: ...
```

ReAct Agent 不依赖具体实现，只依赖这三个 Protocol。你可以把 LLM 换成 Claude、记忆换成 MongoDB、工具换成 MCP Server——ReAct 代码一行不改。

### 2.2 `planner.py` — Plan-and-Execute（330 行）

#### 三阶段流程

```
plan(query)
  → LLM 生成 JSON: {"subtasks": [{id, title, action_type:"tool"|"reasoning", tool_name, ...}]}
  → 返回 List[SubTask]

execute(plan, query, session_id)
  → 逐个执行子任务:
    - action_type=="tool"   → 调用工具，记录 observation
    - action_type=="reasoning" → LLM 基于已有结果推理，输出结论
  → 最后用 LLM 汇总所有结果 → 生成 Final Answer
  → 如果任何子任务失败 → 返回 error，触发 replan

replan(plan, results, error)
  → LLM 基于 "已完成结果 + 错误信息" 重新生成子任务列表
  → 如果全部完成返回 {"subtasks":[]}
```

#### 降级设计（3 层）

```python
# 第 1 层：plan 生成失败 → 降级为单步推理
try:
    raw = await self._llm.acomplete(messages, temperature=0.3)
    return _parse_subtasks(data)
except:
    return [SubTask(id="fallback_1", title="直接回答", action_type="reasoning")]

# 第 2 层：execute 失败 → replan（最多 max_replan_attempts 次）
for attempt in range(self.max_replan_attempts + 1):
    res = await self.execute(current_plan, ...)
    if res.success: return res
    current_plan = await self.replan(...)

# 第 3 层：replan 也失败 → 编排器降级到 ReAct（见 orchestrator.py）
```

#### `_LLMAdapter` — LLM 接口统一

```python
class _LLMAdapter:
    """无论 ModelRouter 返回什么对象，统一包装为 acomplete 接口"""
    async def acomplete(self, messages, **kwargs):
        fn = getattr(self._llm, "acomplete", None)
        if callable(fn):
            return await fn(messages, **kwargs)
        fn2 = getattr(self._llm, "complete", None)
        if callable(fn2):
            return await asyncio.to_thread(fn2, messages, **kwargs)
        raise TypeError("LLM 需实现 acomplete 或 complete")
```

## 3. RAG 全链路

### 3.1 `rag_service.py` — RAG 统一服务（689 行，最大文件）

#### 自研 BM25（从零实现 Okapi 算法）

```python
class _BM25:
    def __init__(self, k1=1.5, b=0.75):  # k1=词频饱和度, b=长度归一化

    def add(self, doc_id, text):
        # 分词 → 统计词频 TF → 更新 DF → 重建 IDF
        tokens = _tokenize(text)  # 中英文混合分词
        for t in tokens:
            tf[t] = tf.get(t, 0) + 1
        # IDF = log(1 + (N - df + 0.5) / (df + 0.5))  ← Okapi 平滑版
        self._idf[t] = math.log(1.0 + (self._N - df + 0.5) / (df + 0.5))

    def search(self, query, top_k):
        # BM25 评分：
        # score = Σ IDF(t) * (f * (k1+1)) / (f + k1*(1-b + b*dl/avgdl))
        for i in range(self._N):
            s += idf * (f * (k1 + 1)) / (f + k1 * (1 - b + b * dl / avgdl))
```

#### RRF 混合检索融合

```python
def hybrid_search(self, query_vec, query_text, top_k):
    vec_results = self.vector_search(query_vec, top_k * 2)  # 语义召回 2 倍
    kw_results = self.keyword_search(query_text, top_k * 2)  # 关键词召回 2 倍

    rrf_k = 60
    for rank, r in enumerate(vec_results):
        scores[r.id] = 1.0 / (rrf_k + rank + 1)       # 向量排第 N 的贡献
    for rank, r in enumerate(kw_results):
        scores[r.id] += 1.0 / (rrf_k + rank + 1)      # 关键词排第 N 的贡献
    # 两路都命中的积累高分 → 按 RRF 总分排序取 top_k
```

**为什么 k=60**：这是 RRF 论文的经验参数，作用是防止单个排名靠前的结果完全主导融合结果。

### 3.2 `rag/retriever.py` — 多路检索引擎（308 行）

```python
class MultiRetriever:
    async def retrieve(self, query, top_k, mode):
        if mode == "vector":   return await self.vector_search(query, top_k)
        if mode == "keyword":  return await self.keyword_search(query, top_k)
        return await self.hybrid_search(query, top_k)

    async def hybrid_search(self, query, top_k):
        # 并行执行两路检索
        vec_task = self.vector_search(query, top_k)
        kw_task = self.keyword_search(query, top_k)
        vec_res, kw_res = await asyncio.gather(vec_task, kw_task)

        # RRF 融合
        return self._rrf_fuse([vec_res, kw_res], top_k)
```

**并行检索**：用 `asyncio.gather` 同时跑向量和关键词，而不是串行等待。

### 3.4 `rag/reranker.py` — Cross-Encoder 重排序（85 行）

```python
class Reranker:
    async def rerank(self, query, documents, top_k):
        model = self._load_model()  # 懒加载 cross-encoder/ms-marco-MiniLM-L-6-v2
        pairs = [(query, d.content) for d in documents]
        scores = await asyncio.to_thread(model.predict, pairs)
        # 按分数降序重排，取 top_k
        ranked = sorted(zip(documents, scores), key=lambda x: -x[1])
        return [doc for doc, score in ranked[:top_k]]
```

**与向量检索的区别**：向量是分别编码 query 和 doc 再算相似度（Bi-Encoder），Cross-Encoder 是把 query+doc 一起喂给模型算相关性分，更准但更慢。所以在粗筛后做精排。

### 5.2 `tools/builtin/calculator.py` — 安全计算器

```python
_ALLOWED_OPS = {ast.Add, ast.Sub, ast.Mult, ast.Div, ast.Pow, ast.USub, ast.UAdd, ast.Mod}

def _eval(self, node):
    # 只允许 AST 白名单中的操作符，禁止函数调用、变量访问
    if isinstance(node, ast.BinOp) and type(node.op) in _ALLOWED_OPS:
        return _ALLOWED_OPS[type(node.op)](left, right)
    raise ValueError("不支持的表达式语法")
```

**安全设计**：用 `ast.parse` 解析表达式后遍历 AST 树，只求值白名单操作符。Agent 无法传 `__import__('os').system('rm -rf /')`，因为 `ast.Call` 不在白名单中。

## 6. 模型路由与韧性

### 6.1 `llm/circuit_breaker.py` — 三态熔断器（128 行）

```
    ┌──────────┐
    │  CLOSED  │  正常放行，累计失败次数
    └────┬─────┘
 失败≥5次 │ 成功→清零
    ┌────▼─────┐
    │   OPEN   │  立即拒绝 RuntimeError，等待 60s
    └────┬─────┘
 60s 后   │
    ┌────▼──────┐
    │ HALF_OPEN │  最多 3 次试探
    └────┬──────┘
 试探成功│失败
    ┌────▼─────┐ ┌──────────┐
    │  CLOSED  │ │   OPEN   │
    └──────────┘ └──────────┘
```

```python
class CircuitBreaker:
    async def call(self, func, *args, **kwargs):
        async with self._lock:  # 并发安全
            if OPEN and 距上次失败≥60s:
                state = HALF_OPEN   # 试探恢复

            if HALF_OPEN and 试探次数≥3:
                raise RuntimeError  # 试探上限

        try:
            result = await func()
            self._record_success()  # 成功→CLOSED
            return result
        except:
            self._record_failure()  # 失败计数+1
            raise
```

**关键细节**：
- `asyncio.Lock` 保证状态切换原子性
- `time.monotonic()` 而非 `time.time()`，不受系统时间调整影响
- HALF_OPEN 失败 → 立即回到 OPEN（不等下一次超时）

### 6.2 `llm/model_router.py` — 多模型路由（172 行）

```python
class ModelRouter:
    def _select_candidates(self, model_preference):
        # 同优先级内加权随机排序：
        scored = [(cfg, random.random() ** (1.0 / max(cfg.weight, 0.01)))
                  for cfg in group]
        scored.sort(key=lambda x: -x[1])
        # weight 越大 → 越容易被排到前面（幂函数变换）

    async def chat(self, messages, model_preference=None, **kwargs):
        candidates = self._select_candidates(model_preference)
        for cfg in candidates:
            try:
                return await breaker.call(self._try_model, cfg.model_id, messages)
            except RuntimeError:  # 熔断打开 → 试下一个
                continue
            except (APIError, RateLimitError, TimeoutError):
                continue  # 自动降级到下一个候选
        raise RuntimeError("所有候选模型均不可用")
```

**算法解释**：`random.random() ** (1.0/weight)` — 假设 weight=3，取 1/3 次方会放大随机数，更可能排在前面。这比简单轮询更灵活，也支持权重调整流量分配。

### 8.2 `etl/chunker.py` — 文档分块（126 行）

三种策略：

| 策略 | 算法 | 适用场景 |
|------|------|---------|
| FIXED | 固定窗口 + overlap 滑动 | 简单文本 |
| PARAGRAPH | 按空行分段合并到目标长度 | 结构化文档 |
| RECURSIVE | 按分隔符递归拆分，过长的用下一级分隔符 | 通用（默认）|

```python
def _chunk_recursive(self, text, separators=["\n\n", "\n", "。", ". ", " "], _depth=0):
    if _depth > 24:             # 防止无限递归
        return self._chunk_fixed(text)  # 退回固定窗口
    if len(text) <= chunk_size:
        return [text]           # 已经够短

    # 按当前分隔符拆分，过长的段落递归用下一级分隔符
    for i, sep in enumerate(separators):
        pieces = text.split(sep)
        for part in pieces:
            if len(part) > chunk_size:
                merged.extend(self._chunk_recursive(part, separators[i+1:], _depth+1))
            else:
                buf += part
```
