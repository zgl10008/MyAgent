### 五、技术模块 → 业务价值映射（面试核心！）

| 技术模块 | 在慢病管理场景的落点 | 面试怎么说 |
|---------|-------------------|-----------|
| **ReAct** | 患者说"头痛"→ Thought: 是否与血压相关 → Action: 查历史血压 → Observation: 今天158/95 → 建议测血压+服药 | "Agent 的多步推理在医疗场景是刚需——症状不是孤立事件，需要关联历史数据、用药记录、生活习惯才能给出安全建议" |
| **Plan-Execute** | 生成月度健康报告 = plan 拆 4 步(收集数据→趋势分析→风险评估→建议) → execute → 汇总 | "慢病管理需要定期生成趋势报告，Plan-Execute 比 ReAct 更适合这类固定的多步工作流" |
| **RAG** | 上传《高血压指南》、药品说明书 → 患者问"降压药什么时候吃最好"→ 检索指南原文 → 引用回答 | "医学知识更新快、专业性强，LLM 不能只靠训练数据回答——RAG 保证每个建议都能追溯到权威指南的具体章节" |
| **混合检索** | "硝苯地平"精确匹配药品名(BM25) + "降压药服用时间"语义理解(向量) | "药品名需要精确匹配不能模糊，但患者口语化的'血压高了怎么办'需要语义理解，这正是混合检索的价值" |
| **三级记忆** | 短期：当前对话中的血压值、症状描述；长期：过去 3 个月血压趋势、用药方案、过敏史 | "慢病管理的核心是连续性——患者昨天说胸痛、今天说好了、明天又痛，Agent 必须记住这些才能发现模式" |
| **熔断器** | LLM API 不可用时，不给出瞎编的医疗建议，而是"暂时无法分析，建议测量血压并观察" | "在医疗场景，不回答比乱回答安全一万倍。熔断器+安全兜底是医疗 AI 的生命线" |
| **反思质检** | Agent 建议"增加硝苯地平剂量"→ 反思 Agent 检查是否提及禁忌症、是否建议咨询医生、是否超出常规剂量 | "医疗 AI 必须有第二道防线。我用独立 LLM 做反思质检，不是因为它100%准确，而是因为两道防线比一道防线安全得多" |

### 八、面试话术模板

#### 3 分钟项目介绍

> "我做了一个**心血管慢病管理 AI Agent**，名字叫心康助手。
>
> **为什么做这个——** 中国 3.3 亿心血管病患者，慢病管理全靠门诊随访根本顾不过来。患者在家不知道血压升高了怎么办、忘了吃药、不知道什么能吃什么不能吃。Agent 正好补这个缺口。
>
> **技术上怎么做——** 核心是自研的 ReAct Agent，患者报一个症状，Agent 会自动查历史血压、检索高血压指南、计算 BMI、检查药物禁忌，然后给出分级建议——正常范围就给生活方式指导，偏高就建议监测，危险就直接让打 120。
>
> **几个关键设计——** RAG 保证每个医学建议都能追溯到指南原文；三级记忆让 Agent 记住患者过去 3 个月的血压趋势和用药方案；反思质检是第二道防线，检出不当建议就拦截；熔断器保证 LLM 挂了的时候不发瞎编的医疗建议。
>
> **前端——** 四个页面：健康咨询、档案管理、血压趋势图、用药打卡。不只是一个聊天窗口，而是完整的慢病管理工具。"

#### 追问：医疗 AI 最大的风险是什么？你怎么处理的？

> "最大的风险是**给出不安全的建议**。我做三层防护：第一层，RAG 强制引用权威指南，Agent 不能靠训练数据瞎编；第二层，反思质检用独立 LLM 审查每个回答，检查是否有遗漏的禁忌症说明；第三层，紧急识别——关键词'胸痛''呼吸困难'直接建议 120，不做任何分析。另外，每句话后面都加'以上建议仅供参考，请遵医嘱'。"

#### 追问：为什么不用现成的医疗 AI（如讯飞医疗）？

> "现成的医疗 AI 是黑盒——你不知道它怎么得出结论的。我这个系统从 ReAct 的 Thought→Action→Observation 到 RAG 的引用来源，每一步都可追溯。患者看到'建议少吃盐'，后面跟着'[1] 中国高血压防治指南2024 第5章'，信任度完全不同。"
