# 心康助手 RAG 检索效果评估报告（面试版）

> 本文档是项目评测体系的对外说明，包含评估方法、量化结果、发现的问题与简历可引用结论。
> 原始数据与复现脚本见 `scripts/` 目录，可直接重跑。

---

## 1. 一句话结论

在心血管慢病知识库（7 份临床指南、270+ 文档块）和 29 条标注查询上，
**混合检索（BM25 + 向量 + RRF 融合）相比纯向量检索 Recall@5 提升 28.3%、MRR 提升 10.2%；
叠加 CrossEncoder 重排序后 MRR 进一步提升 9.8%**。

---

## 2. 评估方法

### 2.1 数据集

| 实验 | 知识库 | 查询数 | 嵌入 | 说明 |
|------|--------|--------|------|------|
| 全知识库（旗舰） | 270 块 / 7 份医学指南 | 29 | paraphrase-multilingual-MiniLM-L12-v2 | 含 rerank 消融 |
| 真实管线验证 | 445 块（Milvus 实库） | 29 | all-MiniLM-L6-v2 | 走真实 RAGService 代码路径 |
| 单篇真实指南 | 32 块（噪声过滤后） | 20 | n-gram 哈希 | 中文医学文献专项 |
| 合成语料（算法自检） | 13 块 / 6 篇文档 | 20 | n-gram 哈希 | 零依赖回归验证 |

知识库来源：中国高血压防治指南（2024）、高血压健康管理规范（2019）、
高血压急症诊治规范（2020）、糖尿病合并高血压患者管理指南（2025）、中西医结合管理指南等。

### 2.2 标注方式

- 查询覆盖四类难度：术语定义（"高血压的诊断标准"）、数据查询（"知晓率/治疗率/控制率"）、
  综合建议（"生活方式干预"）、交叉推理（"糖尿病肾病合并高血压如何选降压药"）。
- Ground truth 采用**关键词 + 语义双路加权自动标注**（避免偏向任一检索器），
  并人工抽查修正；部分查询在知识库中无对应内容时明确标注为 0 相关，不人为剔除。

### 2.3 指标

Recall@K（召回率）、Precision@K（精确率）、NDCG@K（位置加权）、MRR（首个相关结果排名）、检索耗时。
消融维度：vector（纯向量）、keyword（BM25）、hybrid（RRF 融合）、hybrid_rerank（CrossEncoder 精排）。

## 4. 评估发现并修复的问题

评测过程不是"跑个数字"，而是真实暴露了两个工程缺陷，均已修复并有回归验证：

1. **BM25 索引重启丢失**：`_MilvusRAGStore` 启动时只加载 Milvus 集合、不重建内存 BM25 索引，
   导致服务重启后 keyword 检索静默返回空、hybrid 悄悄退化为纯向量。
   修复：启动时从 Milvus 批量查询内容重建 BM25（见 `rag_service.py::_rebuild_bm25`）。
2. **中文分词粒度过粗**：原 `_tokenize` 用"整段正则"分词，中文整句被当作一个词，
   关键词检索对中文基本失效。修复：统一为 jieba 分词，与评估脚本一致，并加入依赖。

这两个问题的修复使真实管线的混合检索从"等于向量检索"恢复到"显著优于向量检索"，
也体现了评测对工程质量的反向验证价值。

## 5. 局限性与后续方向

- Ground truth 以自动标注为主（关键词 + 语义双路），精度低于纯人工标注；后续扩大人工标注规模。
- rerank 单次平均 15.5s，成本高，生产上只对 top-30 候选精排且可异步化。
- 当前仅评估检索召回，未覆盖生成答案质量；下一步增加 LLM-as-judge 的答案正确性/一致性评估。

## 7. 复现方式

```bash
# 1. 全知识库评估（需 Python 3.11+，模型走本地缓存）
python scripts/eval_full_kb.py

# 2. 真实管线验证（需 Milvus Lite 知识库，见 scripts/eval_queries.json）
python scripts/eval_rag.py

# 3. 轻量评估（离线，零外部依赖）
python scripts/eval_rag_standalone.py
python scripts/eval_real_doc.py
```

> 本机复现时如遇模型下载，可设置 `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`
> 使用 HuggingFace 本地缓存。
