### 2.2 读取优先级与降级链

```
PersistentMemoryManager.get_relevant(session_id, query)
        │
        ├── ① LongTermMemory.recall(query, session_id)
        │       └── 语义向量召回 3 条 → 插入结果最前面（重要性最高）
        │
        ├── ② Redis ShortTermMemory.get_relevant()
        │       ├── 成功 → 返回 [LTM结果...] + [Redis最近8条...]
        │       └── 失败 → 标记 redis_ok=False，进入③
        │
        ├── ③ PostgreSQL SessionRepository.get_recent_messages()
        │       ├── 成功 → 返回 [LTM结果...] + [PG最近8条...]
        │       └── 失败 → 标记 pg_ok=False，进入④
        │
        └── ④ _InMemoryMemoryManager.get_relevant()
                └── 始终可用 → 返回 [LTM结果...] + [内存最近8条...]
```

源码对应（[persistent_memory.py:194-223](../app/core/persistent_memory.py#L194-L223)）：

```python
async def get_relevant(self, session_id, query, limit=8):
    items = []

    # 1) Redis 热路径
    if self._redis_ok and self._redis_stm is not None:
        try:
            items = await self._redis_stm.get_relevant(session_id, query, limit)
            if items:
                return await self._append_long_term(items, session_id, query, limit)
        except Exception:
            self._redis_ok = False        # ← 一次失败即标记不可用，避免反复尝试

    # 2) PostgreSQL
    if self._pg_ok:
        try:
            items = await self._pg.get_recent_messages(session_id, limit)
            if items:
                return await self._append_long_term(items, session_id, query, limit)
        except Exception:
            self._pg_ok = False

    # 3) 兜底
    items = await self._fallback.get_relevant(session_id, query, limit)
    return await self._append_long_term(items, session_id, query, limit)
```

**关键设计**：`_redis_ok` 和 `_pg_ok` 是实例级别的熔断标记——一旦某层失败，后续请求直接跳过该层，直到进程重启。这避免了每次请求都在故障层上超时等待。

## 三、短期记忆（ShortTermMemory）

位于 [app/core/memory/short_term.py](../app/core/memory/short_term.py)。

### 3.1 存储结构

**Redis 数据模型**：

```
Key:   stm:session:{session_id}
Type:  List
Value: JSON 序列化的消息对象（按时间追加）

示例:
  RPUSH stm:session:abc123 '{"role":"user","content":"你好","metadata":{}}'
  RPUSH stm:session:abc123 '{"role":"assistant","content":"你好！...","metadata":{...}}'
  ...
  LRANGE stm:session:abc123 0 -1  →  返回所有消息
```

### 3.2 初始化与配置

```python
# short_term.py:24-48
class ShortTermMemory:
    def __init__(self, redis_client, llm, window_size=20, max_tokens=4000):
        self._redis = redis_client
        self._llm = llm                              # ← 用于摘要压缩的 LLM（ainvoke 协议）
        self.window_size = window_size               # ← 最大保留消息条数
        self.max_tokens = max_tokens                 # ← 触发压缩的 token 阈值

```

### 3.3 读写操作

**写入消息**：

```python
# short_term.py:95-104
async def add_message(self, session_id, message):
    key = self._key(session_id)
    await self._redis.rpush(key, self._serialize(message))  # ← 尾部追加
    await self._compress_if_needed(session_id)               # ← 写入后立即检查是否需要压缩
```

**读取历史**：

```python
# short_term.py:79-93
async def get_history(self, session_id):
    key = self._key(session_id)
    raw_list = await self._redis.lrange(key, 0, -1)   # ← 全量读取
    messages = []
    for raw in raw_list:
        if isinstance(raw, bytes):
            raw = raw.decode("utf-8", errors="replace")
        messages.append(self._deserialize(str(raw)))
    return messages
```

**供 Agent 使用的协议适配**：

```python
# short_term.py:178-205
async def get_relevant(self, session_id, query, limit=8):
    """满足 MemoryLike 协议：返回格式化的历史字符串。"""
    msgs = await self.get_history(session_id)
    recent = msgs[-limit:]                                # ← 取最近 N 条
    return [f"{m.role.value}: {m.content}" for m in recent]

async def append_turn(self, session_id, role, content, metadata=None):
    """满足 MemoryManager 协议：直接构造 Message 并写入。"""
    msg = Message(role=MessageRole(role), content=content, metadata=metadata or {})
    await self.add_message(session_id, msg)
```

### 3.4 LLM 摘要压缩（核心机制）

#### 触发条件

两个条件满足**任一**即触发压缩（[short_term.py:106-122](../app/core/memory/short_term.py#L106-L122)）：

```python
async def _compress_if_needed(self, session_id):
    n = await self._redis.llen(key)                     # ← 当前消息数
    msgs = await self.get_history(session_id)
    total_tokens = sum(self._count_tokens(m.content) for m in msgs)

    if n <= self.window_size and total_tokens <= self.max_tokens:
        return  # ← 未触发阈值，跳过压缩

    if len(msgs) < 2:
        return  # ← 少于 2 条消息，不值得压缩
```

| 触发条件 | 默认阈值 | 说明 |
|----------|----------|------|
| 消息数超窗口 | `n > 20` | 防止 Redis List 过长 |
| Token 超限 | `total_tokens > 4000` | GPT-4 上下文窗口 8K，4000 预留一半给 system + 新回复 |

#### 压缩策略

```
压缩前（25 条消息）:
[msg1] [msg2] [msg3] ... [msg15] [msg16] [msg17] ... [msg25]
◄────── to_summarize ──────► ◄────── keep=10 ───────────►
      调用 LLM 压缩为摘要             保留不压缩
```

```python
# short_term.py:124-145
keep = max(2, self.window_size // 2)  # = max(2, 10) = 10
if keep >= len(msgs):
    keep = len(msgs) - 1              # ← 至少保留 1 条确保有东西可保留

to_summarize = msgs[:-keep]           # ← 前面的消息
tail = msgs[-keep:]                   # ← 最近 10 条保留原文

# 调用 LLM 生成摘要
summary_text = await self._summarize_messages(to_summarize)

# 构建摘要消息（以 system 角色存储）
summary_msg = Message(
    role=MessageRole.SYSTEM,
    content=f"[历史摘要]\n{summary_text}",
    metadata={"compressed_from": len(to_summarize)},  # ← 记录压缩量
)

# 重建 Redis List：摘要 + 保留的尾部
await self._redis.delete(key)
for m in [summary_msg, *tail]:
    await self._redis.rpush(key, self._serialize(m))
```

**压缩后**（11 条）：

```
[[历史摘要] 之前15条对话的核心内容...] [msg16] [msg17] ... [msg25]
◄────── 1 条摘要消息 ────────────► ◄────── 10 条原文 ──────►
```

#### LLM 摘要 Prompt

```python
# short_term.py:149-172
async def _summarize_messages(self, messages):
    lines = [f"{m.role.value}: {m.content}" for m in messages]
    prompt = (
        "请将以下对话压缩为简洁中文摘要，保留关键事实与用户意图：\n\n"
        + "\n".join(lines)
    )
    raw = await self._llm.ainvoke(prompt)
    # 提取 content 字段（兼容多种 LLM 返回格式）
    if hasattr(raw, "content"):
        return str(raw.content).strip()
    if isinstance(raw, dict) and "content" in raw:
        return str(raw["content"]).strip()
    return str(raw).strip()
```

**设计要点**：
- 摘要以 `role=system` 身份插入——Agent 看到它是系统级上下文而非对话消息
- `[历史摘要]` 前缀让 Agent 明确知道这是压缩后的内容
- `metadata.compressed_from` 记录被压缩的消息数，用于调试
- LLM 不可用时退回截断（`"\n".join(lines)[:2000]`）

#### 为什么保留尾部而非全部压缩？

| 方式 | 效果 |
|------|------|
| 全部压缩 | 丢失最近的对话细节——"刚才你说的那个药"无法被理解 |
| 只保留尾部 | 最近上下文完整保留，对话连贯性不受影响 |
| 当前方案（压缩前部 + 保留尾部） | 远的历史压缩为要点，近的上下文保留原文——最佳平衡 |

#### Token 计数

```python
# short_term.py:53-57
def _count_tokens(self, text):
    if self._encoding is None:
        return max(1, len(text) // 4)      # ← 降级估算（中文约 1 token ≈ 1.5-2 字符）
    return len(self._encoding.encode(text)) # ← tiktoken cl100k_base 精确计数
```

### 3.5 序列化

消息以 JSON 字符串存储在 Redis List 中：

```python
# short_term.py:59-77
def _serialize(self, msg: Message) -> str:
    return json.dumps({
        "role": msg.role.value,      # ← "user" | "assistant" | "system"
        "content": msg.content,
        "metadata": msg.metadata,
    }, ensure_ascii=False)

def _deserialize(self, raw: str) -> Message:
    d = json.loads(raw)
    return Message(
        role=MessageRole(d["role"]),
        content=d["content"],
        metadata=d.get("metadata") or {},
    )
```

## 四、长期语义记忆（LongTermMemory）

位于 [app/core/memory/long_term.py](../app/core/memory/long_term.py)。

### 4.1 与短期记忆的本质区别

| 维度 | ShortTermMemory | LongTermMemory |
|------|----------------|----------------|
| 存储引擎 | Redis List | Milvus 向量数据库 |
| 检索方式 | 时间倒序取最近 N 条 | 语义向量相似度召回 |
| 检索条件 | 仅 session_id | session_id + 语义相似度 |
| 生命周期 | 单会话内，压缩后逐步淘汰 | 跨会话持久化 |
| 适用信息 | 本轮对话上下文 | 用户偏好、历史重要事实 |
| 写入触发 | 每条消息自动写入 | 需显式调用 `store()` |
| 相似度度量 | — | COSINE / L2（取决于 Milvus 配置） |

### 4.2 存储

```python
# long_term.py:77-108
async def store(self, session_id, content, metadata):
    memory_id = str(uuid.uuid4())
    vec = self._embed.embed_query(content)

    row = {
        self.pk_field: memory_id,        # ← "pk": UUID
        self.vector_field: vec,          # ← "embedding": 384-dim
        self.content_field: content,     # ← "content": 文本内容
        self.session_field: session_id,  # ← "session_id": 所属会话
        self.meta_field: json.dumps(meta, ensure_ascii=False),
    }
    self._coll.insert([row])             # ← 写入 Milvus
    self._coll.flush()                   # ← 确保持久化
    return memory_id
```

**Milvus Collection Schema**（预期）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `pk` | VARCHAR | UUID 主键 |
| `embedding` | FLOAT_VECTOR(384) | 语义向量 |
| `content` | VARCHAR | 记忆文本 |
| `session_id` | VARCHAR | 所属会话 ID |
| `meta` | VARCHAR | JSON 元数据 |

### 4.3 召回

```python
# long_term.py:110-154
async def recall(self, query, session_id, top_k=5):
    vec = self._embed.embed_query(query)               # ① 查询向量化

    # ② 构造过滤表达式：只召回当前会话的记忆
    sid = session_id.replace("'", "\\'")               # ← SQL 注入防护
    expr = f'{self.session_field} == "{sid}"'

    # ③ Milvus 向量搜索 + 表达式过滤
    out = self._coll.search(
        data=[vec],
        anns_field=self.vector_field,                  # ← ANN 检索字段
        param=self.metric_param,                       # ← {"metric_type": "L2", "params": {"nprobe": 16}}
        limit=top_k,
        expr=expr,                                     # ← 会话过滤
        output_fields=[self.pk_field, self.content_field, self.meta_field],
    )

    # ④ 解析结果
    items = []
    for hit in out[0]:
        items.append(MemoryItem(
            id=hit.entity.get("pk"),
            content=hit.entity.get("content"),
            score=hit.distance,                        # ← L2 距离（越小越好）
            metadata=json.loads(hit.entity.get("meta")),
        ))
    return items
```

**关键设计：session_id 过滤**

召回时的 `expr` 过滤确保只返回**当前会话**的历史重要信息，而非所有用户的所有记忆。这是基于一个合理假设：不同会话可能涉及不同主题，跨会话记忆可能造成干扰。

### 4.4 删除

```python
# long_term.py:156-173
async def forget(self, memory_id):
    mid = memory_id.replace("'", "\\'")
    expr = f'{self.pk_field} == "{mid}"'
    self._coll.delete(expr)        # ← 按主键删除
    self._coll.flush()
```

```python
    conversation_id: Mapped[str]     # FK → conversations.id, CASCADE 删除
    role: Mapped[str]                # "user" | "assistant" | "system" | "tool"
    content: Mapped[str]             # 消息文本（TEXT 类型，无长度限制）
    token_count: Mapped[int | None]  # 预留：token 计数
    meta: Mapped[dict | None]        # JSON 扩展（如 trace_id, agent_mode）
    created_at: Mapped[datetime]     # 创建时间

    conversation = relationship("Conversation", back_populates="messages")
```

### 5.2 SessionRepository 设计

```python
# session_repository.py:17-38
class SessionRepository:
    """PostgreSQL 会话持久化仓库。
    每个方法独立获取/释放 session，不依赖 HTTP 请求上下文，
    可直接被 AgentService 单例调用。"""

    @staticmethod
    async def _get_session() -> AsyncSession:
        """从全局工厂获取一个异步 session。"""
        factory = db_session.async_session_factory
        if factory is None:
            raise RuntimeError("数据库未初始化")
        return factory()
```

**关键设计**：不使用 FastAPI 的 `Depends` 依赖注入（因为它需要 HTTP 请求上下文），而是每个方法自己获取和释放 SQLAlchemy AsyncSession。这使得 AgentService（一个应用级单例）可以在任何上下文中使用 SessionRepository。

### 6.2 实现

```python
class _InMemoryMemoryManager:
    def __init__(self):
        self._sessions: dict[str, list[dict]] = {}       # ← session_id → 消息列表
        self._session_meta: dict[str, dict] = {}          # ← session_id → 元数据

    async def get_relevant(self, session_id, query, limit=8):
        history = self._sessions.get(session_id, [])
        recent = history[-limit:]                         # ← 取最近 limit 条
        return [f"{m['role']}: {m['content']}" for m in recent]

    async def append_turn(self, session_id, role, content, metadata=None):
        if session_id not in self._sessions:
            self._sessions[session_id] = []
        self._sessions[session_id].append({
            "role": role, "content": content, "metadata": metadata or {}
        })
        # 自动生成标题（首条 user 消息）
        if role == "user" and self._session_meta.get(session_id, {}).get("title") == "新对话":
            title = content.strip()[:30].replace("\n", " ")
            self._session_meta[session_id]["title"] = title if title else "新对话"
```

**接口兼容性**：与 `ShortTermMemory` 和 `SessionRepository` 实现完全相同的协议（`get_relevant` / `append_turn` / `list_sessions` / `delete_session`），确保上层代码无需区分。

### 7.2 LLM 适配器

ShortTermMemory 的压缩 LLM 需要 `ainvoke` 方法（返回带 `content` 属性的对象），而 Orchestrator 的 LLM 只暴露 `acomplete`（返回字符串）。需要一个适配器：

```python
        # 包装为类 LangChain AIMessage 对象
```

### 7.3 双写策略

```python
# persistent_memory.py:250-273
async def append_turn(self, session_id, role, content, metadata=None):
    # 1. 内存兜底：同步写入（始终执行，始终成功）
    await self._fallback.append_turn(session_id, role, content, metadata)

    # 2. PostgreSQL：异步写入（失败仅日志警告，不阻塞）
    if self._pg_ok:
        try:
            await self._pg.add_message(session_id, role, content, metadata)
        except Exception:
            logger.warning("PG append_turn 失败")

    # 3. Redis：异步写入（失败仅日志警告）
    if self._redis_ok and self._redis_stm is not None:
        try:
            await self._redis_stm.append_turn(session_id, role, content, metadata)
        except Exception:
            logger.warning("Redis append_turn 失败")
```

**一致性模型**：最终一致性。内存兜底是同步的（保证不丢数据），PG 和 Redis 是异步的（不阻塞对话响应）。

```python
# persistent_memory.py:225-248
async def _append_long_term(self, short_items, session_id, query, limit):
    """如果启用了长期语义记忆，将召回结果插入最前面。"""
    if self._long_term is None:
        return short_items

    ltm_items = await self._long_term.recall(query, session_id, top_k=3)
    if ltm_items:
        semantic = [f"[历史记忆] {item.content}" for item in ltm_items]
        combined = semantic + short_items       # ← 语义记忆插入最前面（重要性最高）
        return combined[:limit]                 # ← 截断到 limit
    return short_items
```

**为什么插入最前面**：Agent 处理消息时，前面的消息对后续推理的影响力更大（LLM 的注意力机制对序列前部的关注度通常更高，且 prompt 中越靠前的内容越容易被模型视为"背景设定"）。

## 八、备选管理器（MemoryManager）

位于 [app/core/memory/manager.py](../app/core/memory/manager.py)。

这是一个更轻量的管理器，直接组合 ShortTermMemory + LongTermMemory（不含 PG 和内存降级）：

```python
class MemoryManager:
    def __init__(self, short_term, long_term):
        self._stm = short_term
        self._ltm = long_term

    async def get_context(self, session_id, query):
        short_msgs = await self._stm.get_history(session_id)        # ← 短期历史
        long_items = await self._ltm.recall(query, session_id, top_k=5)  # ← 长期语义召回
        return MemoryContext(
            session_id=session_id,
            short_term_messages=short_msgs,
            long_term_items=long_items,
        )
```

**与 PersistentMemoryManager 的关系**：

| 维度 | PersistentMemoryManager | MemoryManager |
|------|------------------------|---------------|
| 存储层级 | 4 层（LTM + Redis + PG + 内存） | 2 层（STM + LTM） |
| 降级机制 | 自动熔断降级 | 无 |
| 使用场景 | 主路径（AgentService） | 简化场景、测试、独立使用 |
| 接口协议 | MemoryManager + MemoryLike | MemoryContext（结构化返回） |

`PersistentMemoryManager` 是项目的主路径，`MemoryManager` 作为轻量备选存在。

## 十一、关键设计决策总结

### 决策矩阵

| 决策 | 选择 | 理由 |
|------|------|------|
| 短期记忆存储 | Redis List (rpush/lrange) | O(1) 追加，O(n) 全量读取可接受（窗口只有 20 条） |
| 压缩策略 | 保留尾部 keep=10，压缩前部 | 最近上下文完整保留，远的历史压缩为要点 |
| 压缩触发 | 消息数>20 或 token>4000 | 双阈值互补——消息少但 token 多也要压缩（长消息场景） |
| Token 计数 | tiktoken cl100k_base | GPT-4 同款分词器，计数精确 |
| 长期记忆存储 | Milvus 向量数据库 | 语义召回必备，COSINE/L2 相似度 |
| 长期记忆隔离 | 按 session_id 过滤 | 不同会话主题不同，跨会话召回可能是噪声 |
| 持久化存储 | PostgreSQL | 成熟的关系型数据库，支持复杂查询和事务 |
| 写入策略 | 内存同步 + PG/Redis 异步 | 性能优先（不阻塞对话响应），内存兜底保证不丢数据 |
| 一致性模型 | 最终一致性 | 对话场景对实时一致性要求不高 |
| 降级策略 | 逐层熔断 | 一次失败即标记不可用，避免每次请求超时 |
| LLM 适配 | _CompressLLMAdapter | 解耦压缩 LLM 接口（ainvoke）和服务 LLM 接口（acomplete） |
| Milvus 适配 | _LTMCollectionAdapter | 解耦 LongTermMemory 的 ORM 接口和 agent_service 的 MilvusClient |
| 压缩摘要角色 | system | Agent 看到 system 消息视为背景知识，而非对话内容 |
| 自动标题 | 首条 user 消息前 30 字符 | 零 token 消耗，用户无需手动命名会话 |

### 四个协议

记忆系统中的组件通过以下协议解耦：

```python
# 1. MemoryLike（ReActAgent 使用）
class MemoryLike(Protocol):
    async def get_relevant(self, session_id, query, limit) -> list[str]: ...
    async def append_turn(self, session_id, role, content, metadata): ...

# 2. MemoryManager（Orchestrator 使用）
class MemoryManager(Protocol):
    async def get_relevant(self, session_id, query, limit) -> list[str]: ...
    async def append_turn(self, session_id, role, content, metadata): ...

# 3. CompressLLMProtocol（ShortTermMemory 压缩用）
class CompressLLMProtocol(Protocol):
    async def ainvoke(self, input, **kwargs) -> Any: ...

# 4. LTMEmbedProtocol / LTMCollectionProtocol（LongTermMemory 用）
class LTMEmbedProtocol(Protocol):
    def embed_query(self, text) -> list[float]: ...
class LTMCollectionProtocol(Protocol):
    def insert/search/delete/flush(...): ...
```

所有组件依赖协议而非具体实现，方便替换和测试。

### 降级全景矩阵

```
                         Redis    PG     Milvus   状态
                         ─────   ────   ──────   ──────
 全功能                   ✅      ✅      ✅      最优
 Milvus 不可用            ✅      ✅      ❌      短期+持久化可用，无语义召回
 Redis 不可用             ❌      ✅      ✅      PG 热路径，语义召回可用
 PG 不可用                ✅      ❌      ✅      Redis 热路径，无持久化
 Redis + PG 不可用        ❌      ❌      ✅      仅内存+语义召回
 全部不可用               ❌      ❌      ❌      纯内存兜底（重启即丢失）
```

任意降级组合下，系统核心功能（对话）不受影响——只是记忆能力和持久化程度递减。
