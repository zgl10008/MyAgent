## 1. RRF 倒数排名融合（项目核心，最可能考）

```python
def rrf_fuse(ranked_lists, k=60):
    """多个排序结果列表（每个是 doc_id 列表，按排名顺序）融合成一个排名。"""
    scores = {}
    for ranked in ranked_lists:
        for rank, doc_id in enumerate(ranked):       # rank 从 0 开始
            scores[doc_id] = scores.get(doc_id, 0.0) + 1.0 / (k + rank + 1)
    return sorted(scores, key=lambda x: -scores[x])
```

**关键点 / 坑**：
- RRF 的用途：向量路的余弦分（0~1）和 BM25 的分数（无上界）**不在同一尺度**，直接加权相加没意义。RRF **只关心排名**，用 `1/(k+rank)` 把排名转成分数再加，天然规避了"分数不可比"的问题。
- `rank` 从 0 开始，所以分母是 `k + rank + 1`（等价于 rank 从 1 起用 `k + rank`）。

**一句话口述**：双路检索的分数量纲不同，直接加权会偏向绝对值大的那一路，RRF 只取排名、用倒数融合，把"谁更靠前"这件事公平地合并起来。

## 2. TF-IDF（BM25 的简化版，可能问区别）

```python
import math

def build_idf(docs):            # docs: 每篇文档的分词列表
    n = len(docs)
    df = {}
    for tokens in docs:
        for t in set(tokens):   # 一篇文档里重复词只算一次 df
            df[t] = df.get(t, 0) + 1
    # 平滑 IDF，避免 log(0)
    return {t: math.log((n + 1) / (df + 1)) + 1 for t, df in df.items()}

def tfidf(query_tokens, doc_tokens, idf):
    tf = {}
    for t in doc_tokens:
        tf[t] = tf.get(t, 0) + 1
    return sum(tf.get(t, 0) * idf.get(t, 0) for t in query_tokens)
```

**关键点 / 坑**：
- 三个概念：TF（词在文档里出现次数）、IDF（词越稀有权重越高）、两者相乘。
- **TF-IDF vs BM25 的区别**（高频追问）：TF-IDF 的 TF 是线性词频；BM25 加了 **TF 饱和（k1）** 和 **长度归一（b）** 两项修正，更符合"词频贡献递减 + 长文档不占便宜"。

**一句话口述**：TF 衡量"这个词在这篇文档里重不重要"，IDF 衡量"这个词本身稀不稀有"，相乘就是词的得分；BM25 是在它基础上加了饱和和长度归一。

## 3. 评估指标：Recall@K / Precision@K / MRR / NDCG（JD 强调评估）

```python
import math

def recall_at_k(retrieved, relevant, k):
    return len(set(retrieved[:k]) & set(relevant)) / len(relevant) if relevant else 0.0

def precision_at_k(retrieved, relevant, k):
    return len(set(retrieved[:k]) & set(relevant)) / k if k else 0.0

def mrr(retrieved, relevant):
    for rank, doc in enumerate(retrieved, start=1):
        if doc in relevant:
            return 1.0 / rank        # 第一个相关结果的排名的倒数
    return 0.0

def ndcg_at_k(retrieved, relevant, k):
    dcg = 0.0
    for rank, doc in enumerate(retrieved[:k], start=1):
        if doc in relevant:
            dcg += 1.0 / math.log2(rank + 1)   # 位置越靠前权重越高（对数衰减）
    idcg = sum(1.0 / math.log2(r + 1) for r in range(1, min(len(relevant), k) + 1))
    return dcg / idcg if idcg > 0 else 0.0
```

**关键点 / 坑**：
- **Recall@K**：相关文档里，前 K 个结果召回了多少比例（查全率）。
- **Precision@K**：前 K 个结果里，有多少比例是相关的（查准率）。
- **MRR**：只关心**第一个相关结果排在第几位**，取排名倒数——衡量"首个正确答案出现得早不早"。
- **NDCG**：考虑**排名位置**，越靠前权重越高（`1/log2(rank+1)`），再用理想排序归一化到 0~1。

**一句话口述**：Recall 看"找没找全"，Precision 看"找得准不准"，MRR 看"第一个对的排第几"，NDCG 看"整体排序质量"——四个指标回答四个不同的问题。

## 4. 滑动窗口切块（overlap）

```python
def chunk(text, chunk_size=512, overlap=64):
    if not text:
        return []
    if len(text) <= chunk_size:
        return [text]
    step = chunk_size - overlap          # 相邻两块重叠 overlap 个字符
    return [text[i:i + chunk_size] for i in range(0, len(text), step)]
```

**关键点 / 坑**：
- `step = chunk_size - overlap`，这样每块和下一块重叠 `overlap` 个字符，避免把一个语义片段从中间切断。
- 最后一块可能不足 `chunk_size`，保留即可（或按需丢弃过短尾块）。
- 项目里实际是**按 token 切**（tiktoken `cl100k_base`，512 token + 64 overlap）而非按字符，因为 LLM 按 token 计费/计长度，按字符切会超 context。可以主动提这一句体现深度。

**一句话口述**：滑动窗口 + overlap 是为了让相邻块有重叠、不把语义切断；实际工程里我按 token 切而不是按字符，因为模型上下文是按 token 算的。

## 5. Top-K（heapq vs sort）

```python
import heapq

def top_k(items, k):                       # items: [(doc, score), ...]
    return heapq.nlargest(k, items, key=lambda x: x[1])

def top_k_stream(iterable, k):             # 数据量大、k 小时的流式版
    heap = []
    for item, score in iterable:
        if len(heap) < k:
            heapq.heappush(heap, (score, item))
        elif score > heap[0][0]:           # 比堆里最小的还大就替换
            heapq.heapreplace(heap, (score, item))
    return sorted(heap, reverse=True)
```

**关键点 / 坑**：
- `heapq.nlargest` 内部用最小堆，复杂度 **O(n log k)**；`sorted` 是 O(n log n)。数据量大、k 小（检索场景 top-5/10）时用堆更省。
- 流式版维护一个**大小为 k 的最小堆**：新元素比堆顶（第 k 名）大就替换，遍历完堆里就是最大的 k 个。

**一句话口述**：检索只要 top-k 时，维护一个大小为 k 的最小堆，O(n log k)，比全量排序 O(n log n) 更省，尤其当 n 很大、k 很小的时候。

## 6. 从 LLM 输出鲁棒提取 JSON

```python
import re, json

def extract_json(text):
    text = (text or "").strip()
    if text.startswith("```"):            # 去掉 markdown 代码围栏
        text = text.strip("`")
        if text.lower().startswith("json"):
            text = text[4:]
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        pass
    m = re.search(r"\{[\s\S]*\}", text)   # 兜底：抓第一个 {...}
    if not m:
        raise ValueError("无法解析 JSON")
    return json.loads(m.group(0))
```

**关键点 / 坑**：
- LLM 输出可能带 markdown 围栏、前后缀废话，不能直接 `json.loads`。
- 用正则 `\{[\s\S]*\}` 兜底抓 JSON 对象；`[\s\S]` 匹配含换行的任意字符。
- **解析失败必须降级**（这是面试加分点）：意图识别失败→关键词规则，反思失败→保守给 50 分，而不是让整个请求崩掉。

**一句话口述**：模型输出不可靠，先剥 markdown 围栏，再用正则抓 JSON，最后解析失败走降级——因为"提示词 + 兜底"要成对设计。
