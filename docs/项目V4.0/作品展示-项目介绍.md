# 心血管慢病管理 AI Agent

> 一个以心血管慢病管理为默认场景的**通用 AI Agent / RAG 平台**。
> 核心解决三个问题：**怎么把大模型接入真实任务、怎么让检索更准、怎么让多轮对话记住上下文**。

---

## 一、一句话定位

这不是一次简单的大模型 API 封装，而是一套具备 **工具调用、知识检索、多步任务编排、分层记忆、故障降级、领域安全控制、执行过程可观测** 的完整 Agent 系统。

```text
通用 Agent / RAG 底座
      +
心血管慢病管理默认 Demo
      +
可插拔领域安全策略
```

---

## 二、项目目标

- 让大模型不止会「聊天」，还能**自主选择工具**完成任务；
- 用**两阶段检索 + 精排**解决中文医学文档检索不准确的问题；
- 用**短 / 长 / 持久三层记忆**解决多轮对话上下文丢失；
- 在医疗这种高风险领域，加上**可插拔的安全边界**，做到「该拦就拦、不该拦不误伤」。

---

## 三、核心能力

### 1. 任务编排（Agent）

- **三级模式路由**：规则快路径 → LLM 语义路由 → ReAct 兜底，兼顾低延迟与语义覆盖，三级降级保证可用性。
- **两种执行范式**：
  - **ReAct**：`Thought → Action → Observation` 循环，根据中间结果动态决定下一步；
  - **Plan-and-Execute**：先规划拆解子任务 → 逐个 ReAct 执行 → 失败重规划 → 汇总，适合复杂多步任务。
- **Function Calling 工具调用后端**：模型返回结构化 `tool_calls`（工具名 + JSON 参数），后端校验后执行，失败自动降级到文本解析后端。
- **工具注册中心**：`calculator`（计算）、`rag_search`（私有知识库检索）、`web_search`（实时搜索），统一注册、统一描述。

### 2. 知识增强（RAG）

- **两阶段检索**：
  1. **召回**：向量路（bge-m3 语义）+ 关键词路（jieba 分词 + BM25），用 **RRF 倒数排名融合**；
  2. **精排**：cross-encoder（bge-reranker-v2-m3）逐对打分重排。
- **向量化**：bge-m3（1024 维，CUDA 本地推理）。
- **带引用生成**：回答附 `[n]` 引用，可追溯到原文片段。

### 3. 三层记忆

| 层级 | 存储 | 职责 |
|------|------|------|
| 短期记忆 | Redis 滑动窗口 + LLM 摘要压缩 | 当前会话近轮上下文 |
| 长期记忆 | Milvus 语义向量 | 跨会话语义关联 |
| 持久化 | PostgreSQL | 会话消息落盘 |

三层各司其职，配合内存降级，任一外部服务不可用都能继续跑。

### 4. 医疗安全边界

- 关键词粗筛 + LLM 确认的**两阶段安全门**；
- 只对「正在发作」的高风险症状（如急性胸痛、呼吸困难）短路返回急诊引导；
- 假设性 / 既往史 / 科普类问题正常放行并附加免责声明，降低误拦率；
- 领域策略做成可插拔的 `DomainPolicy`，通用底座与业务解耦。

### 5. 反思闭环（Reflection）

- 对高风险回答做质量评分 + 幻觉检测；
- 低质量回答自动修正或完整重试，形成「生成 → 评估 → 修正」闭环。

### 6. 可观测性

- 每次请求记录 `trace_id`、执行步骤、`thought / action / observation`、工具调用、反思评分、降级状态；
- 前端实时展示 Agent 推理步骤、工具调用日志、检索引用，方便调试与演示。

## 四、技术架构

```
┌────────────── 接入层 ──────────────┐
│  FastAPI  /chat/agent /chat/rag   │
│  /rag/ingest（文档上传）           │
└────────────────┬──────────────────┘
                 ▼
┌──────────── Agent 编排层 ────────────┐
│  安全门 → 记忆 → 意图识别 → 模式路由  │
│  → 编排执行(ReAct/Plan-Execute)     │
│  → 反思闭环 → 回写记忆              │
└────────┬───────────────┬────────────┘
         ▼               ▼
┌──── 能力层(工具) ──┐ ┌──── 记忆层 ────┐
│ calculator         │ │ 短期 Redis     │
│ web_search         │ │ 长期 Milvus    │
│ rag_search         │ │ 持久 PG        │
└────────┬───────────┘ └───────────────┘
         ▼
┌──────────── 检索层 RAG ────────────┐
│ BM25+向量 → RRF 融合 → cross-encoder│
│ bge-m3(1024维,CUDA) + bge-reranker  │
│ Milvus Lite 向量存储               │
└────────────────────────────────────┘
```

## 七、可演示场景（实测通过）

1. **RAG 知识问答**：上传指南后提问，回答带引用溯源；
2. **ReAct 多步推理**：数学计算走 `calculator` 工具，展示 Thought→Action→Observation；
3. **医疗安全拦截**：急诊症状被安全门短路，直接引导就医；
4. **多轮记忆**：第 2 轮能准确回忆第 1 轮的姓名、病史；
5. **Plan-and-Execute**：复杂问题自动拆解为「规划 → 子任务执行 → 汇总」。

---

## 八、项目亮点总结

1. **Agent 不是单一模式**——三级路由 + ReAct + Plan-and-Execute + Function Calling，展示完整编排能力；
2. **RAG 不只是向量搜索**——双路召回 + RRF + 精排，量化提升显著；
3. **考虑真实工程问题**——外部服务、模型、向量库、Redis 任一不可用都有降级兜底；
4. **通用底座与领域策略解耦**——不是边界模糊的「万能 Agent」，可扩展到教育、法律等领域。
