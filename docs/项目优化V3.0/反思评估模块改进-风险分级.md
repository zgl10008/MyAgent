# 反思评估模块改进：风险分级执行（方案 C）

> 现状：反思闭环对所有 Agent 回答**全量执行**，只有一个全局开关 `_enable_reflection`，没有按任务风险分层。
> 本文设计"风险分级"改进方案——按任务风险等级决定反思策略，高风险必反思、中风险轻量反思、低风险跳过，兼顾质量与成本。

---

## 一、背景与问题

### 1.1 现状

[orchestrator.py:311](../../app/core/agent/orchestrator.py#L311) 的反思触发条件：

```python
if self._enable_reflection and answer and self._reflection_loop is not None:
    # 反思闭环：评估 → 修正 → 可能重试
```

只有三个条件：① 全局开关打开 ② 有回答 ③ 反思循环存在。**没有按意图、是否调工具、置信度、降级状态做任何区分**。

### 1.2 问题

| 任务类型 | 幻觉风险 | 反思价值 | 现状 |
|------|------|------|------|
| 知识问答 / 实时搜索 | 高 | 高（有检索证据可对照） | 反思 ✅ |
| 复杂多步推理 | 中高 | 高 | 反思 ✅ |
| 数学计算（calculator 确定性） | 低 | 低 | **浪费** |
| 文档管理（结构化操作） | 低 | 低 | **浪费** |

| 闲聊（"你好""谢谢"） | 几乎无 | 几乎无 | **浪费** |
| 无工具调用的简单直答 | 低 | 低（无证据，反思 = 凭空判断） | **浪费** |

两个核心浪费点：

1. **低风险任务白白多花至少 1 次反思 LLM 调用**（token + 延迟）。
2. **无工具调用时反思没有证据可对照**——[evidence_collector.py](../../app/core/agent/evidence_collector.py) 只收集 `rag_search` / `web_search` 的返回，`calculator` 和闲聊不进 evidence。没证据的反思是"让裁判闭眼打分"。

### 1.3 设计目标

1. 高风险任务（医疗知识问答、实时搜索）**必反思**，宁多花 token 也要防幻觉。
2. 低风险任务（闲聊、确定性计算、无证据直答）**跳过**，省 token 省延迟。
3. 中风险任务**轻量反思**（只修不重试）。
4. **不降低高风险任务的质检门槛**——砍的是低价值任务，不是砍安全底线。

## 二、风险分级模型（核心）

### 2.1 五个风险因子

全部是**链路里已有的信息**，不需要新增 LLM 调用、不需要新基础设施，纯函数打分，确定、可测试、零成本：

| 因子 | 来源 | 说明 |
|------|------|------|
| **意图类型** `intent` | `IntentContext.intent` | 知识问答/实时搜索风险高，闲聊/计算低 |
| **检索证据** `has_evidence` | `steps` 里是否有 rag_search/web_search | 有证据反思才有意义 |
| **意图置信度** `confidence` | `IntentContext.confidence`（0~1） | 置信度低 = 意图可能判错 = 风险更高 |
| **降级状态** `degraded` | orchestrator 计算 | FC→正则降级后解析失败率高，风险高 |
| **领域** `domain` | 请求参数 | 医疗场景整体上调 |

### 2.2 评分表

```
风险分 = 意图分 + 证据分 + 置信度分 + 降级分 + 领域分
```

| 因子 | 取值 | 分值 |
|------|------|------|
| 意图：知识问答 | — | +50 |
| 意图：实时搜索 | — | +50 |
| 意图：数学计算 | — | −40 |
| 意图：文档管理 | — | −20 |
| 意图：闲聊对话 | — | −50 |
| 意图：其他/未知 | — | +30（保守，未知当偏高） |
| 证据：有 rag_search/web_search | — | +20 |
| 证据：无工具调用 | — | 0 |
| 置信度：< 0.55 | 意图可能判错 | +20 |
| 置信度：0.55 ~ 0.80 | 中等 | 0 |
| 置信度：> 0.80 | 稳定 | −10 |
| 降级：degraded = True | 解析失败率高 | +20 |
| 降级：无 | — | 0 |
| 领域：cardiovascular | 医疗 | +10 |
| 领域：general / 其他 | — | 0 |

### 2.3 分档

```
风险分 ≥ 65  → R3 高风险
风险分 30~64 → R2 中风险
风险分 < 30  → R1 低风险
```

### 2.4 示例验证

| 场景 | 计算 | 风险分 | 等级 |
|------|------|------|------|
| 知识问答 + 有证据 + 高置信 + 无降级 + 医疗 | 50+20−10+0+10 | 70 | R3 ✅ |
| 实时搜索 + 有证据 + 低置信 + 无降级 + 医疗 | 50+20+20+0+10 | 100 | R3 ✅ |
| 知识问答 + 无证据 + 低置信 + 有降级 + 医疗 | 50+0+20+20+10 | 100 | R3 ✅ |
| 知识问答 + 无证据 + 高置信 + 无降级 + 通用 | 50+0−10+0+0 | 40 | R2 ✅ |
| 文档管理 + 无证据 + 高置信 + 无降级 + 医疗 | −20+0−10+0+10 | −20 | R1 ✅ |
| 闲聊 + 无证据 + 高置信 + 无降级 + 医疗 | −50+0−10+0+10 | −50 | R1 ✅ |
| 数学计算 + 无证据 + 高置信 + 无降级 + 医疗 | −40+0−10+0+10 | −40 | R1 ✅ |

## 三、等级 → 动作映射

| 等级 | 反思策略 | LLM 调用量 | 说明 |
|------|------|------|------|
| **R3 高风险** | 完整反思（现有逻辑） | 1 次评估 + 可能 1 次修正 + 最多 2 次重试 | ≥80过 / 60-79修 / <60重试 |
| **R2 中风险** | 轻量反思 | 1 次评估 + 最多 1 次修正 | 只打分 + SelfCorrector，**不触发完整 Agent 重试** |
| **R1 低风险** | 跳过反思 | 0 | 直接返回，`reflection_report=None` |

R2 的关键设计：`<60` 分时**降级为 SelfCorrector 单次修正**，而不是重跑整个 Agent——因为中风险任务的"错"通常是措辞/细节问题，不值得 N 步 ReAct 重跑。

## 四、数据结构与代码设计

### 4.1 新增模块 `app/core/agent/reflection_gating.py`

```python
# -*- coding: utf-8 -*-
"""反思风险分级：按任务风险决定反思策略，避免低风险任务浪费 LLM 调用。"""

from __future__ import annotations

from enum import Enum
from typing import Any


class RiskLevel(str, Enum):
    """反思风险等级。"""

    R3_HIGH = "r3_high"      # 完整反思（评估 + 修正 + 可能重试）
    R2_MEDIUM = "r2_medium"  # 轻量反思（评估 + 修正，不重试）
    R1_LOW = "r1_low"        # 跳过反思


# 意图 → 风险基础分
_INTENT_SCORE: dict[str, int] = {
    "知识问答": 50,
    "实时搜索": 50,
    "数学计算": -40,
    "文档管理": -20,
    "闲聊对话": -50,
}
_UNKNOWN_INTENT_SCORE = 30  # 未知意图保守按偏高处理

_EVIDENCE_ACTIONS = {"rag_search", "web_search"}

# 分档阈值
R3_THRESHOLD = 65
R2_THRESHOLD = 30


def _has_retrieval_evidence(steps: list[dict[str, Any]]) -> bool:
    """steps 中是否包含检索类工具调用（有证据反思才有意义）。"""
    return any(s.get("action") in _EVIDENCE_ACTIONS for s in steps)


def score_risk(
    *,
    intent: str,
    confidence: float,
    steps: list[dict[str, Any]],
    degraded: bool,
    domain: str = "general",
) -> int:
    """计算风险分。纯函数，无副作用，便于单元测试。"""
    score = _INTENT_SCORE.get(intent, _UNKNOWN_INTENT_SCORE)

    # 证据分
    if _has_retrieval_evidence(steps):
        score += 20

    # 置信度分
    if confidence < 0.55:
        score += 20
    elif confidence > 0.80:
        score -= 10

    # 降级分
    if degraded:
        score += 20

    # 领域分
    if domain == "cardiovascular":
        score += 10

    return score


def classify_risk(score: int) -> RiskLevel:
    """风险分 → 风险等级。"""
    if score >= R3_THRESHOLD:
        return RiskLevel.R3_HIGH
    if score >= R2_THRESHOLD:
        return RiskLevel.R2_MEDIUM
    return RiskLevel.R1_LOW


class ReflectionGating:
    """反思分级器：对外唯一入口，返回该任务的风险等级。"""

    def decide(
        self,
        *,
        intent: str,
        confidence: float,
        steps: list[dict[str, Any]],
        degraded: bool,
        domain: str = "general",
    ) -> RiskLevel:
        score = score_risk(
            intent=intent,
            confidence=confidence,
            steps=steps,
            degraded=degraded,
            domain=domain,
        )
        return classify_risk(score)
```

## 五、orchestrator 改动点

在 [orchestrator.py:305](../../app/core/agent/orchestrator.py#L305) 反思闭环前，插入分级决策：

```python
# ── 反思闭环：先分级，再决定执行策略 ──
reflection_report: Optional[ReflectionReport] = None
correction_applied = False
reflection_warnings: list[str] = []
retries_made = 0

risk_level = RiskLevel.R3_HIGH  # 默认保持原行为（分级未启用时）
if self._enable_reflection_gating:  # 新开关
    risk_level = self._gating.decide(
        intent=intent_ctx.intent,
        confidence=intent_ctx.confidence,
        steps=steps,
        degraded=degraded,
        domain=getattr(intent_ctx, "domain", "general"),
    )

if risk_level == RiskLevel.R1_LOW:
    # 低风险：跳过反思，直接返回
    self._tracer.log_event(trace_id, "reflection.skip", {"risk": "r1_low"})

elif self._enable_reflection and answer and self._reflection_loop is not None:
    allow_retry = (risk_level == RiskLevel.R3_HIGH)  # R2 不重试
    max_retries = self._reflection_max_retries if allow_retry else 0
    try:
        loop_result = await self._reflection_loop.evaluate_and_improve(
            user_query=user_input,
            answer=answer,
            steps=steps,
            allow_retry=allow_retry,
        )
        answer = loop_result.final_answer
        ...
        while (
            allow_retry
            and loop_result.action_taken == "retry_needed"
            and retries_made < max_retries
            ...
        ):
            ...
    except Exception as e:
        ...
```

```python
async def evaluate_and_improve(
    self,
    user_query: str,
    answer: str,
    steps: list[dict[str, Any]],
    allow_retry: bool = True,   # ← 新增

    ...
    if score < 60:
        if allow_retry:
            return ReflectionLoopResult(
                action_taken="retry_needed", retry_context=ctx, ...
            )
        # 中风险：降级为单次修正，不重跑 Agent
        corrected = await self._corrector.correct(answer, report, evidence)
        ...
```

## 七、边界情况

| 情况 | 处理 |
|------|------|
| 意图识别失败（intent 未知/空） | `_UNKNOWN_INTENT_SCORE=+30`，保守按中高风险处理，不跳过 |
| 知识问答但没调工具（无证据） | 意图 +50，无证据 0 → 通常落在 R2 或 R3（见示例），仍会反思 |
| 降级 + 低置信叠加 | 双 +20，必然进入 R3，符合"越不确定越要质检" |
| 反射本身异常 | 沿用现有 try/except，跳过反思不影响返回 |
| 分级未启用（灰度期） | `risk_level` 默认 R3，行为与现在完全一致 |

**关键安全约束**：任何"不知道、不确定"的情况，都**偏向反思**而不是跳过——宁可多花一次调用，也不放过高风险任务。

## 八、测试计划

新增 `tests/test_reflection_gating.py`，纯函数便于穷举测试：

```python
# 1. 高风险 → R3
assert score_risk(intent="知识问答", confidence=0.88,
                  steps=[{"action": "rag_search"}],
                  degraded=False, domain="cardiovascular") >= 65

# 2. 低风险闲聊 → R1
```

集成测试：验证 orchestrator 在 R1 时 `reflection_report is None`、R2 时不触发重试、R3 时行为不变。

## 九、收益估算

假设低风险（闲聊 + 数学计算 + 文档管理 + 无证据直答）占总请求约 **20%~30%**，则：

| 指标 | 现状（全量反思） | 分级后 |
|------|------|------|
| 低风险任务反思调用 | 每请求 ≥1 次 | **0 次** |
| 中风险任务重试上限 | 2 次 | **0 次**（只修） |
| 高风险任务 | 不变 | **不变** |

- 低风险请求直接省掉反思调用 → 省 **20%~30%** 的反思 token + 对应延迟。
- R2 砍掉重试路径，中风险请求最坏情况从"评估 + 2 次重试 + 修正"降到"评估 + 1 次修正"。
- 高风险任务（医疗知识问答）**一点没省**，安全底线不动。

> 注：占比是假设值，实际需用线上 trace 统计各意图分布后精确计算。

## 十、权衡与医疗场景注意

1. **分级不是"按省成本排序一刀切"，而是"把反思资源从低价值任务转移到高价值任务"**。
2. 医疗场景（cardiovascular）整体 +10，知识问答 + 检索类任务天然落在 R3，**不会被误跳过**。
3. 阈值 65/30 是经验值，上线前应：
   - 抽一批回答人工打分，校准反思裁判可信度；
   - 用线上数据 A/B 验证：分级开启后，高风险任务的反思准确率是否保持不变、低风险任务的漏检率是否可接受。
4. 最坏情况兜底：即使分级误判把高风险划成低风险，还有 **DomainPolicy 的急诊关键词短路**在更上游兜底，安全链路没有单点依赖反思。

---

## 十一、总结

> 反思没必要所有任务都执行。方案 C 用"意图 + 检索证据 + 置信度 + 降级 + 领域"五个现有因子打风险分，≥65 完整反思、30~64 只修不重试、<30 跳过。纯函数打分零额外成本，高风险任务（医疗知识问答）必反思、低风险任务（闲聊/计算）跳过，未知情况保守偏向反思。相比全量执行，省掉低风险任务和重试的浪费，同时不动医疗安全底线。
