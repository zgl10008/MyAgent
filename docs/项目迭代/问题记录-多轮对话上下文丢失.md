# 问题记录：多轮对话上下文丢失（FunctionCall 后端未注入历史）

> 记录日期：2026-08-10
> 涉及模块：`app/core/agent/function_call_agent.py`、`app/core/agent/react_agent.py`、`app/core/agent_service.py`
> 状态：已修复并补充回归测试

---

## 一、现象

用 Agent 连续提问三轮：

1. 你是什么大模型？
2. 同类型公司有哪些？
3. 我前面提问了几个问题？

前两轮回答正常，但第三轮模型回答："这是我们的第一次交流，您之前还没有提过其他问题，所以前面提问的问题是 0 个。"

模型"真的"不知道前面问过什么，说明最终生成环节完全没有拿到会话历史。

---

## 二、定位过程

### 1. 前端

`frontend/src/pages/ChatPage.tsx` 会把本地累积的完整消息列表随 `conversation_id` 一起发给 `/chat/agent`，`agent_mode` 固定为 `react`。

### 2. 后端入口

`app/api/routes/chat.py` 的 `/chat/agent` 调用 `AgentService.chat()`。而 `agent_service.py` 只取 `request.messages[-1].content`（最后一条），**前端传的完整历史被丢弃**，多轮上下文完全依赖后端记忆系统：

```python
user_text = request.messages[-1].content if request.messages else ""
```

### 3. 记忆读取的去向

`agent_service.chat()` 中读到的 `history` 只用于两件事：

- 意图识别 `IntentRecognizer.recognize(..., context={"history": history})`
- 模式路由 `ModeRouter.resolve(..., history=history)`

真正生成答案的编排环节没有收到这份历史，而是依赖各 Agent 自己再读一次记忆。

### 4. 关键转折：执行后端被切换成了 Function Calling

`AgentService.__init__` 会尝试创建 `FunctionCallAgent`，成功后调用：

```python
self._orchestrator.set_function_call_agent(self._function_call_agent)
```

`orchestrator.py` 中 `set_function_call_agent()` 会把 `_use_function_calling` 置为 `True`。此后所有 `react` 模式的执行都走 `FunctionCallAgent.run()`，而不是带记忆的正则版 `ReActAgent`。

### 5. 根因落点

`function_call_agent.py` 的循环里：

```python
messages = _build_messages(query, system_text, history, [])
```

`mem_snippets` 被**硬编码为空列表**；`session_id` 只出现在注释里，从未被读取。模型每一轮收到的 prompt 只有当前这一句问题——这就是"第一次交流 / 0 个问题"的直接原因。

### 6. 对比：正则版 ReAct 是有记忆的

`react_agent.py` 在运行前会：

```python
mem_snippets = await self._memory.get_relevant(session_id, query, limit=8)
```

并把结果拼成"检索记忆摘要"放进 system prompt。说明记忆系统本身是通的，**只是 FC 后端漏接了线**。

---

## 三、根因总结

- **主因**：`FunctionCallAgent` 作为后加的"ReAct 工具调用后端升级"，接入时只注册了工具 Schema，漏接了会话记忆读取，导致每轮都是无状态单轮。
- **次因**：`ReActAgent` 内部会在产出最终答案时写一次 assistant 记忆，`agent_service.chat()` 结束又会再写一次 user + assistant，造成重复；且 `plan_execute` 模式下每个子任务的 ReAct 结果也会被当作 assistant 消息写进会话记忆，污染历史。

---

## 四、修复内容

### 1. `app/core/agent/function_call_agent.py`

- 新增 `memory: Optional[MemoryLike] = None` 构造参数（复用 `react_agent.MemoryLike` 协议）。
- `run()` 中从 context 读取 `session_id`，循环前调用 `get_relevant(session_id, query, limit=8)`，把结果传给 `_build_messages`，与 `ReActAgent` 行为对齐。

### 2. `app/core/agent_service.py`

- 构造 `FunctionCallAgent` 时传入 `memory=self._memory`。

### 3. `app/core/agent/react_agent.py`

- 移除最终答案分支里的 `append_turn`，记忆写入统一收敛到 `agent_service.chat()`（user + assistant 各一次），避免重复写入和 plan_execute 子任务污染。

### 4. 测试

- 新增 `tests/test_function_call_agent.py`：验证 FC 后端把会话历史注入 system prompt；无记忆时保持单轮行为。
- `tests/test_react_agent.py` 新增用例：锁定 ReAct 内部不再写记忆，防止回归。

---

## 五、验证

- 新增/涉及用例：`test_function_call_agent.py` + `test_react_agent.py` 共 10 个，全部通过。
- 完整测试套件：**70 passed**（临时环境，Python 3.11）。
- 附带发现：本机存在用户级环境变量 `DEBUG=release`，会覆盖 `.env` 的 `DEBUG=true` 导致 pydantic-settings 启动报错（README 已有警告），验证时临时以 `DEBUG=false` 运行，未改动用户环境。

---

## 六、修复后的链路

```
请求 → 读记忆（意图识别 / 模式路由）
     → 编排器（react / plan_execute）
         → FC 或 ReAct 各自 get_relevant 注入 system prompt（带历史）
     → 生成最终答案
     → agent_service 统一写入 user + assistant 到记忆
```

---

## 七、遗留问题与后续建议

1. **前端全量历史被丢弃**：`/chat/agent` 只取最后一条消息。可在记忆不可用时，把 `request.messages[:-1]` 作为兜底上下文。
2. **记忆降级是进程内 dict**：Redis/PG 不可用时重启即丢，可考虑落盘或 SQLite 持久化。
3. **方案 B（触发式注入）**：只有检测到追问/指代才读历史，仍是成本优化方向，见 `改进方向-多轮上下文意图路由.md`。
4. **建议补充真实多轮集成测试**：用真实 API 连续问三连问，断言模型能数出"前面提问 2 个问题"。
