# 问题记录：搜索问答卡在步骤 1 + 右侧面板内容溢出

> 记录日期：2026-08-10
> 涉及模块：`app/core/agent/function_call_agent.py`、`app/core/agent_service.py`、`frontend/src/components/AgentSteps.tsx`
> 状态：已修复并补充回归测试

---

## 一、现象

接入百度搜索后出现两个问题：

1. 界面右侧"分析进度"面板中，部分内容（主要是搜索摘要里的长链接）超出屏幕范围。
2. 部分带检索的问答只执行到步骤 1 就卡住：回答区空白，没有任何最终答案。

---

## 二、问题 2 定位过程（后端卡步骤 1）

用真实 DeepSeek API + 百度搜索复现，拿到关键报错：

```
openai.BadRequestError: Error code: 400
An assistant message with 'tool_calls' must be followed by tool messages
responding to each 'tool_call_id'. (insufficient tool messages following
tool_calls message)
```

### 根因

`FunctionCallAgent` 一轮请求里如果模型返回**多个工具调用**（例如同时搜两个关键词），
组装消息历史时会在循环里为每个工具调用都追加一条携带全部 `tool_calls` 的 assistant 消息：

```python
for tc in response.tool_calls:
    history.append(AIMessage(content=..., tool_calls=response.tool_calls))  # 重复追加
    history.append(ToolMessage(...))
```

结果发给模型的消息里出现了多余的 assistant(tool_calls) 消息，OpenAI 兼容接口
（DeepSeek）直接返回 400。Agent 以失败收场，前端只显示第 1 步、回答为空，
看起来就像"卡住了"。

---

## 三、问题 1 定位过程（前端溢出）

百度搜索结果中的链接形如 `http://www.baidu.com/link?url=...`（100+ 字符且无空格），
右侧面板固定 320px（`w-80`），`AgentSteps` 的摘要文本用了 `font-mono` 且没有断行策略，
长串 URL 直接撑破容器。

---

## 四、修复内容

### 1. `app/core/agent/function_call_agent.py`

- assistant 消息改为**只追加一次**，随后为每个工具调用追加一条对应的 `ToolMessage`
  （`tool_call_id` 一一对应），满足 OpenAI/DeepSeek 的消息约束。

### 2. `app/core/agent_service.py`

- 失败兜底：当 Agent 无回答但有 `error` 时，把错误文本作为回复内容返回，
  避免前端出现"步骤 1 + 空白回答"的假卡死。

### 3. `frontend/src/components/AgentSteps.tsx`

- 思考/摘要/异常文本统一加 `min-w-0` + `break-words`；摘要框（含长链接）加
  `break-all whitespace-pre-wrap`，长串可换行，不再撑破右侧面板。

### 4. 测试

- `tests/test_function_call_agent.py` 新增用例：一次返回多个 `tool_calls` 时，
  第二轮请求的消息必须为 `[System, Human, AIMessage, ToolMessage x N]`，
  `tool_call_id` 顺序对应，且 assistant 消息不重复。

---

## 五、验证

- 完整测试套件：**77 passed**。
- 真实链路复现（DeepSeek + 百度）：
  - 修复前：模型一次发起 2 个搜索 → 下一轮 400 → 步骤 1 卡住、回答空白。
  - 修复后：模型一次发起 2 个搜索 → 正常进入下一轮 → 输出完整答案（2 步），
    无 400 报错。

---

## 六、遗留与后续建议

1. `FunctionCallAgent` 使用同步 `self._llm.invoke()`，会阻塞事件循环；
   并发场景建议改为 `ainvoke`。
2. 多次搜索会让单轮问答耗时较长（2 次百度搜索约 10~20 秒），可考虑给 ReAct
   循环增加"同轮最多 N 个工具调用"或超时上限的约束。
